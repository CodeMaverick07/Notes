dd:
Linux DD (Disk to Disk) 
The Linux dd command is one of the most powerful utility which can be used in a variety of ways. 
This tool is mainly used for copying and converting data, hence it stands for data duplicator. 
This tool can be used for:
•	Backing up and restoring an entire hard drive or a partition.
•	Creating virtual filesystem and backup images of CD or DVDs called ISO files
•	Copy regions of raw device files like backing up MBR (master boot record).
•	Converting data formats like ASCII to EBCDIC.
•	Converting lowercase to uppercase and vice versa.

Converting case of a file(lowercase)--->lcase
			 (uppercase)--->ucase

	#cat>/test.txt
	#HELLO
	ctrl+d
	
	~]#dd  if=/test.txt  of=/test1.txt   conv=lcase
	#cat test1.txt

if===input file
of===output file
conv===conversion

Types of Process:
1. Normal process		gedit, firefox
2. Zombie process		
	a. Zombie is a leftover bit of a dead process that hasn’t been cleaned up properly
	b. A zombie process is a process that has completed its execution but still remains in the process table because 			       		its parent process has not yet read its exit status.
	c. Once this is done using the wait system call, the zombie process is eliminated from the process table.
	d. Zombie processes don't use any system resources but they do retain their process ID. If there are a lot of zombie processes, then all 		the available process ID’s are monopolized by them.


3. Orphan process
		a. An orphan process is a process that is still executing, but whose parent has died. 

		b. When the parent dies, the orphaned child process is adopted by init or systemd (process ID 1).

		c. When orphan processes die, they do not remain as zombie processes.

4. Daemon process		background process (sshd, ntpd)
				A daemon process is a background process that is not under the direct control of the user.

	Signal name	Signal number			Description
 	
	SIGTERM		      15	 		Kill the process gracefully.

 	SIGINT		      2	 			This is the signal that is sent when we press Ctrl + C. It 								aims to interrupt the process, but the process may ignore it.

 	SIGKILL		      9	 			This signal also interrupts the process but it does so 									unconditionally (use with care!) since a process cannot ignore it.

 	SIGHUP		      1	 			Short for “Hang UP”, this signals instructs daemons to reread its 							configuration file without actually stopping the process.

 	SIGTSTP		      20			Pause execution and wait ready to continue. This is the signal that 							is sent when we type the Ctrl + Z key combination.

 	SIGSTOP		      19	 		The process is paused and doesn’t get any more attention from the 							CPU cycles until it is restarted.

 	SIGCONT		      18			This signal tells the process to resume execution after having 								received either SIGTSTP or SIGSTOP. This is the signal that is sent 							by the shell when we use the fg or bg commands.

•	SIGHUP - Hangup, sent to a process when the controlling terminal is closed. For example, if you closed a terminal 		 window that had a process running in it, you would get a SIGHUP signal. So basically you've been hung up 		 on.

•	SIGINT - Is an interrupt signal, so you can use Ctrl-C and the system will try to gracefully kill the process.

•	SIGTERM - Kill the process, but allow it to do some cleanup first.

•	SIGKILL - Kill the process, kill it with fire, doesn't do any cleanup.

•	SIGSTOP - Stop/suspend a process.

To create raid array:
#mdadm    --create     /dev/md0     --level=5  --raid-devices=3   /dev/sdb1    /dev/sdc1     /dev/sdd1 
#mdadm  --detail   /dev/md0

To make sde1 faulty
#mdadm   --manage   /dev/md0   --fail   /dev/sdc1
#mdadm  --detail  /dev/md0


To remove faulty disk partition in raid array (/dev/sdc1)
#mdadm   --manage   /dev/md0   --remove  /dev/sdc1
#mdadm  --detail  /dev/md0

To add new disk partition in raid array (/dev/sde1)
#mdadm   --manage   /dev/md0   --add   /dev/sde1
#mdadm  --detail  /dev/md0

rsync: smart copy (incremental copy)
1. rsync is a free command-line tool
2. Efficiently sync files and directories between two hosts or machines
3. Files that do not exist on the remote-host are copied.
4. Files that have been updated will be synced, rsync will copy only the changed parts of files to the remote host.
5. files that are exactly the same are not copied to the remote host.

#mkdir /profit
#cd /profit
#touch a b c d
#mkdir sales

1. To copy content of /profit on nw shared folder:
on Server:


#rsync -rv  /profit/*     10.0.0.2:/shared-folder    
-r---Recursively  	 but does not keep file ownership, permissions, timestamps, or symbolic links.
-v---versbose
OR
#rsync -av  /profit/*     10.0.0.2:/shared 
-a---archive  same as -r but keeps all file permissions, symbolic links, file ownership, etc.



2. To sync the timestamp too:
#rsync -rtv  /profit/*     10.0.0.2:/shared

Special Permission
1. Sticky Bit			1		t		applicable only on others(o)
2. SUID	Set UserID		4		s		applicable only on owner(u)
3. SGID Set GroupID		2		s		applicable only on group(g)	



1. sticky bit		

	If we set the sticky bit on a directory, a file/folder under this directory can be deleted/renamed/moved only by either the owner of the file/directory or the root user. Sticky bit will restrict rest of the users from renaming/deleting/moving existing files/folders, however they can work on their own data.

To set sticky bit:
================
		1.#chmod 1777  /reports

			or
		2.#chmod o+t  /reports
To verify:
==========	ls -ld /reports

		drwxrwxrwt		root		root			reports

To remove sticky bit:
===================
		1.#chmod 0777  /reports

			or
		2.#chmod o-t  /reports


============================================================================================================
2. SUID	(Set user ID):	4		s			working on owner(u) 

A file with SUID always executes as the user who owns the file, regardless of the user passing the command. Any user can use the command set with SUID bit, even though user is not the owner of the command.

#ll  /usr/bin/passwd		SUID bit is set on passwd, because of this, all the users can execute this command, although root is owner.

		#rwsrwxrwx		root			root		/usr/bin/passwd

To set SUID bit:
================
		1.#chmod 4777  /usr/bin/passwd

			or
		2.#chmod u+s  /usr/bin/passwd
To verify:
==========	#ll  /usr/bin/passwd

		drwsrwxrwx		root		root			/usr/bin/passwd

To remove SUID bit:
===================
		1.#chmod 0777  /usr/bin/passwd

			or
		2.#chmod u-s  /usr/bin/passwd
========================================================================================
 
3. SGID  (Set Group ID):		2		s			working on groups(g)

If the SGID bit is set on any directory, all subdirectories and files created inside will get the same group ownership as the main directory, it doesn't matter who is creating it


To set SGID bit:
================
		1.#chmod 2777  /reports

			or
		2.#chmod g+s  /reports
To verify:
==========	#ls -ld  /reports

		drwxrwsrwx		root		root			reports

login as user1:
		$cd /reports

		$touch a.txt b.txt

		$ls -ld  /reports

		-rwxrwxr--	user1		root			a.txt
		-rwxrwxr--	user1		root			b.txt

as above, owner is user1, as he logged in and created files, but duo to SGID bit is set, group ownership is retained to root only.

To remove SUID bit:
===================
		1.#chmod g-s  reports

ACL in Linux	related to permissions
setfacl		setting acl / permission of folder/file
getfacl		to verify  ACL permissions of folder/file


#mkdir  /demo

drwxr-xr-x		root		root		demo


to assign explicit permission for group user-admin---> no access
		setfacl -m group:user-admin:---   /demo
		getfacl /demo

to assign explicit permission for Terry--->read,exeute
		setfacl -m user:Terry:rx  /demo
		getfacl /demo

to assign explicit permission for smith--->Full access
		setfacl -m u:smith:rwx   /demo
		getfacl /demo

to remove the explicit permission for user smith
		setfacl -x u:smith /demo
		getfacl /demo


to remove all the explicit permission from the /demo
		setfacl -b /demo
		getfacl /demo

IP address can be set using

To assign ip address temporarily, Changes made with ip are lost after reboot.

	#ip addr add 192.168.1.10/24 dev ens33

	1. #ifconfig
	2. #ifconfig ens33
	3. #ip a
	4. #ip a  s

2. Identify the connection name:
	#nmcli connection show

3. To modify/assign the connection for static IP:
	# nmcli con mod "ens33" ipv4.addresses 192.168.1.1/24   ipv4.gateway   192.168.1.100   ipv4.dns  "8.8.8.8,8.8.4.4" 	ipv4.method manual

	# nmcli con up "ens33"

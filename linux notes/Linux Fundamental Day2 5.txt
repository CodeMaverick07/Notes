device files:  are stored in /dev
Types of Devices:
1.	Character devices: transmits data char by char. eg keyboard, mouse
2.	Block devices: transmits blocks of data. Faster than character devices. eg USB, DVD-ROMs, Hard drives.

#ll /dev

Types of Files:
1.Regular files (-): It contain programs, executable files and text files.
2.Directory files (d): It is shown in blue color. It contain list of files.
3.Special files:
	o Block file (b)
	o Character device file (c)
	o Named pipe file (p): Pipes are unnamed objects created to allow two processes to communicate. One process reads and the other process writes to the pipe file. This unique type of file is also called a first-in-first-out (FIFO) file.
	o Symbolic link file (l)
	o Socket file (s): A socket is a special file used for inter-process communication, which enables communication between two processes.

Hard Link & Soft Link
Links are created to have exact replica between two files.

There are two types of links.
1. Hard Link
2. Soft Link

1. Hard Link:
a. A hard link is an identical replica of the original file.
b. Both files (the hard link and the original file) will have the same inode number.
c. A hard link is another file that directly references the same data on disk as the original. 
d. cannot link directories.
e. Saves disk space.
f. Faster data access than soft link.


To create Hard link:

mkdir  links
cd links
links]#cat>h1.txt
		this is demo of hard link
	ctrl+d
links]# ln h1.txt   h2.txt

links]# ll
links]#  ls -i		-i  to see the inode number,  inode number is a location of a file

Verify the content of h2.txt
			cat h2.txt

delete original file
		#rm -f h1.txt
Still second file is accessible
		
		#cat h2.txt

2. Soft Link:
a. A soft link, also known as a symbolic link.
b. Functions similarly to a shortcut or pointer to a file.
c. A soft link is a file that points to another file, similar to a Windows shortcut.
c. It is not an exact replica of the file, but rather a pointer to the original.
d. Inode number will be different
e. You will not be able to access the contents of the soft link if you remove the actual file.
f. Can be used to linked directories.
g. Slower data access than hard link

To create Soft Link:
links]#cat>s1.txt
		this is demo of soft link
	ctrl+d
links]# ln  -s  s1.txt   s2.txt				-s for soft link

links]# ll

links]#  ls -i		
two different inode numbers  for s1 & s2

Verify the content of s2.txt
			#cat s2.txt

delete orginal file
		#rm -f s1.txt
s2 file will become inaccessible
		#ll				shows red color broken link
		#cat s2.txt
			will give error---no such file/directory

Working with run levels/targets in RHEL7

 To check the default run level/target name
	#systemctl get-default

 To get the default run level
	#systemctl set-default  <target name>
===========================================================
Commonly used targets:

 0 (Halt): poweroff.target			
 1 (Single-user): rescue.target
 3 (Multi-user, CLI): multi-user.target
 5 (Multi-user, GUI): graphical.target
 6 (Reboot): reboot.target
    Emergency shell
 
a. To verify the current default boot state (runlevel)
	#ls -lt /etc/systemd/system/default-target

b. To see all active Targets: 
	#systemctl list-units --type=target or runlevel

c. To see all active/inactive loaded Targets: 
	#systemctl list-units  --type=target  --all



d. Set Default Target (Permanent): 
	#systemctl set-default multi-user.target
		or
	#systemctl set-default graphical.target

e. To change Target (Temporary): 
	#systemctl isolate multi-user.target

Working with GRUB--->Grand Unified Bootloader

1. Grub is software that manages the startup process of a Linux based computer 
2. It displays a menu allowing users to select between different OS/Kernel.
3. As per the choice/selection, it will load respective kernel and initramfs in the RAM.
4. In case of no selection, GRUB will loads the default OS kernel after 5 seconds.
5. Also it transfer the control of hardware to that respective kernel.

1. /etc/default/grub----> Main file for modifying timeout, default OS, and kernel command-line parameters.
2. /boot/grub2/grub.cfg---->Final configuration file
3. /etc/grub2.cfg	----------> linked file to /boot/grub2/grub.cfg

GRUB2 Bootloader Timeout & Title

1. vim /etc/default/grub

	GRUB_TIMEOUT=15

#Change this line
	GRUB_DISTRIBUTOR="MyRHEL7"

esc:x


2. Regenerate the GRUB Configuration:

	#grub2-mkconfig -o /boot/grub2/grub.cfg

3. To Verify:

	#reboot

Root password recovery:  allows you to reset the root's pwd:

1. Reboot your system. 
2. On the GRUB menu screen, press e to edit the default boot entry.
3. Locate the line beginning with linux16 & navigate to the end of this line(using end button), after UTF-8, type   	rd.break


4. Press Ctrl+x to boot the system in emergency shell, provide root's pwd.

5. The root filesystem is mounted as read-only. Remount it with write permissions using:
	#mount | grep /sysroot
	#mount -o remount,rw /sysroot

6. Switch to the root environment by running:
	#chroot /sysroot

7.Reset Password:
	#passwd root


8. To prevent authentication failures due to SELinux, ensure the filesystem is relabeled on boot. Or else SELinux will prevent the access to system as we used rd.break, and did pwd resetting.
	#touch /.autorelabel

The touch /.autorelabel command creates an empty, hidden file named .autorelabel in the root directory. 
9.	#exit
10. 	#exit

Booting Process of Linux (RHEL7):


Power ON → POST (BIOS/UEFI) → GRUB2 Boot Loader → Kernel + Initramfs → systemd (PID 1) → Target Services Start → Login Prompt



P = Power ON
B = BIOS/UEFI + POST
G = GRUB2
K = Kernel
I = Initramfs
S = Systemd + Services
L = Login Prompt


1. Power ON:
============
	1. Press the power button.
	2. The computer receives power and starts.


2. BIOS/UEFI Checks Hardware (POST):
====================================
	1. BIOS/UEFI checks whether hardware is working properly:
		RAM
		CPU
		Keyboard
		Hard Disk
This is called POST (Power-On Self-Test).

3. Boot Loader (GRUB2) Starts:
=============================
	1. BIOS/UEFI finds the boot loader.
	2. In Linux, the boot loader is usually GRUB2.
	3. GRUB2 displays the boot menu and selects the Linux kernel.


4. Kernel Loads:
===============
	1. GRUB2 loads the Linux Kernel into memory.
	2. The kernel is the heart of the operating system.
	3. It starts controlling the hardware.


5. Initramfs Loads:
==================
	1. A temporary file system called initramfs is loaded into RAM.
	2. It contains drivers required to access the real root filesystem.
	3. After finding the actual filesystem, control is transferred to it.

6. systemd (PID 1) Starts:
=========================
	1. The kernel starts systemd.
	2. systemd is the first process and has PID 1.
	3. It manages all services and startup tasks.

7. Services Start:
=================
	1. Essential services are started:
	2. Network service
	3. Firewall
	4. SSH
	5. Database services
	6. Other background services
	7. System prepares itself for users.

8. Login Prompt Appears:
=======================
	1. CLI login screen or GUI login screen is displayed.
	2. User can enter username and password and start working.
